## 기획 한 줄 요약 (5문장)

내 홈페이지는 **내가 찍은 사진을 소개하는 곳**이다.  
방문자는 **마음에 드는 사진에 응원 버튼을 누른다**.  
서버에는 **어떤 사진을 응원했는지와 시각을 저장한다**.  
저장 후 화면에는 **사진마다 응원 횟수가 보인다**.  
**다른 기기에서 새로고침해도 같은 숫자가 나오면** 완성이다.

## 1. 화면 구성

### 사진 카드 (3개)

```
┌──────────────────────────────┐
│  [사진 이미지]               │
│  사진 제목                   │
│                              │
│  [응원하기 🤍]   3회         │
│  저장 중… / 결과 메시지      │
└──────────────────────────────┘
```

| 요소 | 설명 |
|---|---|
| 사진 이미지 | `index.html`에 하드코딩 (src 경로 직접 지정) |
| 사진 제목 | `index.html`에 하드코딩 |
| 응원하기 버튼 | 클릭 시 Netlify Function 호출 |
| 응원 횟수 | 페이지 로드 시 Supabase에서 조회, 버튼 클릭 성공 후 즉시 갱신 |
| 피드백 메시지 | 버튼 아래 1줄 텍스트 |

### 사진 ID 목록 (하드코딩)

| 화면 제목 | `photo_id` 값 |
|---|---|
| 사진 1 | `photo-01` |
| 사진 2 | `photo-02` |
| 사진 3 | `photo-03` |

> 사진 제목은 추후 실제 제목으로 변경한다.

## 2. 버튼 상태별 동작

| 상태 | 버튼 | 화면 메시지 |
|---|---|---|
| 대기 | 활성화 | (없음) |
| 저장 중 | 비활성화(`disabled`) | "저장 중…" |
| 저장 성공 | 재활성화 | "응원이 저장되었습니다 ✓" → 2초 후 사라짐 |
| 저장 실패 | 재활성화 | "저장에 실패했습니다. 다시 시도해 주세요." |
| 없는 사진 ID | — | 서버 거절 → 실패 메시지 표시 |

**규칙:** Supabase INSERT 응답을 받기 전에는 성공 메시지를 절대 표시하지 않는다.

## 3. 저장 데이터 (Supabase)

### 테이블: `reactions`

| 컬럼 | 타입 | 설명 |
|---|---|---|
| `id` | `uuid`, PK | 자동 생성 (`gen_random_uuid()`) |
| `photo_id` | `text`, NOT NULL | `photo-01`, `photo-02`, `photo-03` 중 하나 |
| `created_at` | `timestamptz` | 자동 기록 (`now()`) |

### 조회 방식

- 페이지 로드 시: `photo_id`별 `COUNT(*)` 조회 → 각 카드에 표시
- 버튼 클릭 성공 후: 해당 카드 숫자만 재조회하여 갱신

### 유효성 검사

- 허용 `photo_id`: `photo-01`, `photo-02`, `photo-03`
- 허용 목록에 없는 값은 Supabase Row Level Security(RLS) 정책으로 INSERT 거절
- 클라이언트 측에서도 버튼 클릭 시 `photo_id` 값 검증

## 4. 배포 서비스: Netlify 선택

### Netlify vs Vercel 비교

| 항목 | Netlify | Vercel |
|---|---|---|
| 정적 HTML 배포 | ✅ 루트 `index.html` 자동 서빙 | ✅ |
| Serverless Function | ✅ `netlify/functions/` 파일 하나 | ✅ `api/` 폴더 |
| 환경 변수 | ✅ 대시보드 설정 | ✅ |
| 무료 함수 호출 | 125,000회/월 | 100,000회/월 |
| 현재 프로젝트 적합성 | ⭐ **더 적합** | 적합 |

**Netlify 선택 이유:** 현재 프로젝트는 `index.html` 단일 파일 구조다. Netlify는 추가 설정 없이 루트 파일을 자동 서빙하고, Function도 파일 하나 추가로 바로 동작한다. Vercel은 Next.js 등 프레임워크에 최적화되어 있어 순수 HTML 프로젝트에는 Netlify가 더 직관적이다.

## 6. 접근 제한

이 기능은 로그인·자유 입력이 없다. 버튼 클릭만 있으므로 별도 인증이 필요 없다.  
대신 아래 두 가지로 잘못된 데이터 저장을 막는다.

1. **Supabase RLS**: `photo_id`가 허용 목록 외이면 INSERT 거절
2. **클라이언트 검증**: 버튼의 `data-photo-id` 속성값이 허용 목록에 없으면 API 호출 자체를 차단

중복 응원은 허용한다. 숫자는 '방문자 수'가 아니라 **누적 응원 횟수**다.

## 7. 검사 방법 (완성 기준)

| 번호 | 검사 항목 | 합격 기준 |
|---|---|---|
| 1 | 기본 동작 | 사진 카드 3개가 보이고 각각 응원 횟수가 표시된다 |
| 2 | 저장 성공 | 버튼 클릭 → "저장 중…" → "응원이 저장되었습니다 ✓" → 숫자 +1 |
| 3 | 실패 메시지 | 네트워크를 끊고 클릭하면 성공 메시지가 뜨지 않는다 |
| 4 | 다기기 동기화 | PC에서 1회, 휴대폰에서 1회 누른 뒤 두 화면 모두 2회 표시 |
| 5 | 잘못된 ID 거절 | 존재하지 않는 `photo_id`로 직접 API 호출 시 저장 거절 |
| 6 | 재배포 후 유지 | Netlify 재배포 후 새로고침해도 기존 집계가 유지된다 |
